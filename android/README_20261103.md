# 신한매크로 APK (안드로이드 앱)

## 구조
- 신호앱 알림 수신 (`NotificationListenerService`)
  → 파싱 (`삼성전자 매수 10주`) → 리스크 검사 → 접근성 서비스로 신한앱 화면 조작
  → 스크린샷 저장 + 앱 알림/텔레그램
- 별도 PC·Termux·ADB 불필요 (폰 앱 하나로 동작)
- 로직은 `core/` (순수 Kotlin, 단위 테스트 36건), 안드로이드 연동은 `app/`

## 설치
- GitHub 저장소 → **Releases** → 최신 `sinhanmacro_v<번호>_<날짜>.apk` 다운로드 → 설치
  - "이 출처 허용" 필요
- **Android 13+ 필수**: 설치 직후 앱 정보 → ⋮ → **제한된 설정 허용**
  - 허용 전에는 접근성/알림 접근이 회색으로 막혀 켤 수 없음
  - 앱 첫 화면의 "앱 정보" 버튼으로 이동

## 앱 안에서 설정 (첫 화면 순서대로)
1. 접근성 서비스 ON ("신한매크로 자동화")
2. 알림 접근 ON ("신한매크로 신호수신")
3. 배터리 최적화 제외 (백그라운드 종료 방지)
4. "설치된 앱 패키지명 검색"으로 신한앱·신호앱 패키지명 확인
5. "설정(JSON) 편집": `app.package`, `signal.source_packages`, `symbols`, `flows` 입력
   - PC에서 작성 → 메신저로 전송 → 복사 → "클립보드 붙여넣기" → 저장 (저장 시 문법·값 검사)
6. flows 작성: 신한앱의 해당 화면을 연 상태에서 "5초 뒤 화면 요소 덤프"
   → 로그에 `text / id / desc / center` 출력 + 클립보드 복사 → 셀렉터 작성
   - 셀렉터 키: `text`, `text_contains`, `text_regex`, `id`, `id_contains`, `desc`, `desc_contains`, `class`, `clickable`, `index`
   - 템플릿 변수: `{code} {name} {qty} {price} {side}`
   - step: `tap`, `tap_xy`(좌표), `type`, `wait`, `wait_for`, `key`(BACK/HOME), `swipe`, `shot`
   - 제출 버튼 step 에 반드시 `"final": true`

## 테스트 순서
1. "검사만" — 파싱 + 리스크 검사
2. 신한앱 **수동 로그인** 후 "실행" (`dry_run: true`) → 제출 직전에 멈추고 캡처 저장
3. 장중 소액(1주) `dry_run: false` 로 실전 테스트
4. 이후 신호앱 알림이 오면 자동 실행

## 업데이트 (앱 실행 시 자동)
- 앱을 열면 GitHub 최신 릴리스(`v<번호>`)와 현재 버전 비교
- 새 버전이 있으면 팝업 → [업데이트] → 다운로드(SHA-256 검증) → 시스템 설치 화면에서 확인
- 수동 확인: 첫 화면 "업데이트 확인"
- 배포 방법(개발자)
  - 기본 브랜치에 push → GitHub Actions 가 테스트·빌드 → 릴리스 `v<빌드번호>` 자동 게시
  - 파일명: `sinhanmacro_v<번호>_<빌드날짜>.apk`
  - 앱 `versionCode` = 빌드번호 (항상 증가)
- 업데이트 설치 시 서명키가 같아야 함 → 키를 바꾸면 기존 앱 삭제 후 재설치

## 최초 1회 설정: 서명 암호 시크릿 (필수)
- 업데이트 설치는 서명키가 매번 같아야 하므로 고정 키가 필요. 키는 저장소에 평문으로 올리지 않음
- 방법 (폰 브라우저에서 가능)
  1. GitHub 저장소 → Settings → Secrets and variables → Actions → **New repository secret**
  2. 이름 `SIGNING_PASSPHRASE`, 값 = 길고 아무도 모르는 문자열 (20자 이상) → 저장
  3. Actions 탭 → **Build APK** → Run workflow
- 동작
  - 첫 실행 때 CI 가 서명키를 생성하고 `SIGNING_PASSPHRASE` 로 **암호화**해 `android/keystore/release.jks.enc` 로 커밋
  - 이후 빌드는 같은 암호로 복호화해 같은 키로 서명 → 앱 내 업데이트 가능
  - 키 생성 후 릴리스(`v<번호>`)가 자동 게시됨
- 주의
  - `SIGNING_PASSPHRASE` 를 잃어버리면 같은 키로 서명 불가 → 앱 삭제 후 재설치 필요 (암호를 따로 보관)
  - 시크릿이 없으면 임시 키로 빌드만 하고 **릴리스는 게시하지 않음** (Actions 의 `apk` 아티팩트로 받을 수는 있으나 업데이트 불가)
  - 암호를 바꾸거나 `release.jks.enc` 를 지우면 키가 새로 생성되어 재설치 필요

## 안전장치
- 허용 종목(화이트리스트)·종목별 `max_qty`·일일 주문 한도·동일 주문 중복 차단·거래시간(평일 09:00~15:20)
- 앱 첫 화면 킬스위치 (모든 주문 차단)
- 대상 앱이 전면에 없거나 다른 앱 화면이면 조작 중단 (엉뚱한 앱 탭 방지)
- 제출 후 확인 실패 시에도 주문 기록 → 중복 주문 방지
- 기본 `dry_run: true`

## 한계 / 주의
- **신한앱이 접근성 서비스 사용을 탐지·차단할 수 있음** → 먼저 접근성 ON 상태에서 신한앱이 정상 실행되는지 확인
- 보안화면(FLAG_SECURE)·보안키패드는 화면 요소·스크린샷이 막힐 수 있음. 로그인은 수동 (생체/간편인증 유지)
- 주문마다 비밀번호를 요구하면 자동화 불가
- 폰 화면 잠금(PIN/패턴)이 있으면 자동 실행 불가 → 잠금 없음 또는 충전 중 화면 유지 권장
- 앱 실행이 막히면 "다른 앱 위에 표시" 허용 후 재시도
- 스크린샷은 Android 11+ (저장 위치: `Android/data/com.sinhanmacro.app/files/shots/`)
- 공휴일 미처리, 지정가는 호가 단위 일치 필요, 신한앱 업데이트 시 flows 재작성
- 약관 위반·계정 제재 가능성, 모든 매매 손익은 본인 책임
- 이 앱은 실제 신한앱/실기기에서 검증되지 않음 → 반드시 `dry_run` 으로 단계별 확인
