# 신한매크로 APK (안드로이드 앱) — 해외주식(미국) 기준

## 구조
- 신호앱 알림 수신 → 파싱 → 리스크 검사
  → 접근성 서비스로 신한앱 조작(종목·주문유형·수량·가격 입력)
  → **주문 직전 화면 검증 → 사용자 승인** → 제출 → 접수 확인
- 별도 PC·Termux·ADB 불필요 (폰 앱 하나로 동작)
- 로직은 `core/` (순수 Kotlin, 단위 테스트 61건), 안드로이드 연동은 `app/`

## 신호 형식
- 예
  - `TMV 매수 10주 지정가 43.38`
  - `TMV SELL 5주 LOC $43.50`
  - `TMV 매수 2주 시장가`
  - `TMV 매수 2주 Stop limit 감지 41.5 지정가 42`
- 방향: 매수/매도/BUY/SELL (둘 다 있거나 없으면 무시)
- 수량: 정수 `N주` (소수점 수량은 거부, 생략 시 symbols 의 `qty`)
- 가격: `@43.38`, `$43.38`, `43.38 USD`, `43.38달러`, `지정가 43.38`, `LOC 43.38` (소수 허용)

## 티커는 정확히 일치해야 주문
- `symbols` 에 등록한 티커만 거래 (등록 안 된 티커는 무시)
- 신호의 티커는 **대소문자까지 동일한 독립 토큰**이어야 함
  - 통과: `TMV`, `[신호] TMV,`, `TMV를`
  - 거부: `tmv`, `TMVX`, `ATMV`, `TMV-3X`, 종목명만 적힌 신호
- 2개 이상 티커가 함께 있으면 거부
- 주문 화면에서도 `verify` 로 같은 티커가 표시되는지 다시 확인 (아래)

## 주문유형 (신한앱 '주문유형 선택' 화면과 동일)
| 신호 표기 | config 키 | 앱 화면 문구 | 가격 |
|---|---|---|---|
| 지정가 / LIMIT | `limit` | 지정가 | 필요 |
| 시장가 / MARKET | `market` | 시장가 | 불필요 (가격이 같이 오면 거부) |
| LOO | `loo` | LOO | 필요 |
| LOC | `loc` | LOC | 필요 |
| Stop limit / 스톱리밋 | `stop_limit` | Stop limit | 감지단가 + 지정가 |
| Vwap | `vwap` | Vwap 지정가 | 필요 |
| Twap | `twap` | Twap 지정가 | 필요 |
- 신호에 유형이 없으면 `order.default_type` (기본 지정가)
- `order.allowed_types` 에 없는 유형은 차단 (기본: 지정가·시장가. 예시 설정: + LOO·LOC)
- stop_limit / vwap / twap 는 입력란이 더 있으므로 flows 에 단계를 추가한 뒤 허용
- 앱 화면 문구가 다르면 `order.type_labels` 로 덮어쓰기 (예: `{"loo": "장시작 지정가"}`)

## 주문 전 확인 (기본 ON)
1. flows 의 입력이 끝나면 `verify` 항목(티커·주문유형·수량·가격)이 **화면에 실제로 표시**되는지 검사 — 하나라도 없으면 중단
2. 제출 직전 화면을 캡처해 **헤드업 알림**으로 표시: `주문 확인 필요` + 요약 + [승인] [거부]
   - 앱 첫 화면에도 승인/거부 버튼 표시 (알림이 안 보일 때)
3. `confirm.timeout_sec`(기본 120초) 안에 승인 안 하면 **취소** (거부와 동일)
4. 승인 후 `verify` 를 다시 검사 (대기 중 화면이 바뀌었는지) → 통과하면 제출
- 알림 권한 필요 (Android 13+ 알림 허용). 첫 화면의 "주문 승인 알림 테스트"로 확인
- `"confirm": {"required": false}` 로 끄면 승인 없이 자동 제출 (권장 안 함)
- `dry_run` 이면 승인 단계 전에 멈춤 (승인 요청 없음)

## verify (주문 직전 화면 검증)
- `flows.buy.verify` / `flows.sell.verify`: 제출 직전에 모두 화면에 있어야 하는 셀렉터 목록
  - 예: `{"label":"티커","sel":{"text_regex":"^{ticker_re}(\\s|$)"}}`
  - `when` 으로 `"priced"`(시장가 제외) 등 조건 지정 가능
- 기본 `safety.require_verify: true` → verify 에 **티커 검증(`{ticker}` 또는 `{ticker_re}`)이 없으면 설정 저장이 거부됨**

## 설치
- GitHub 저장소 → **Releases** → 최신 `sinhanmacro_v<번호>_<날짜>.apk` 다운로드 → 설치
  - "이 출처 허용" 필요
- **Android 13+ 필수**: 설치 직후 앱 정보 → ⋮ → **제한된 설정 허용**
  - 허용 전에는 접근성/알림 접근이 회색으로 막혀 켤 수 없음 (첫 화면의 "앱 정보" 버튼)

## 앱 안에서 설정 (첫 화면 순서대로)
1. 접근성 서비스 ON ("신한매크로 자동화"), 알림 접근 ON ("신한매크로 신호수신")
2. 알림 허용(승인 알림용), 배터리 최적화 제외
3. "설치된 앱 패키지명 검색"으로 신한앱·신호앱 패키지명 확인
4. "설정(JSON) 편집": `app.package`, `signal.source_packages`, `symbols`, `flows` 입력
   - PC에서 작성 → 메신저로 전송 → 복사 → "클립보드 붙여넣기" → 저장 (저장 시 문법·값 검사)
5. flows 작성: 신한앱의 해당 화면을 연 상태에서 "5초 뒤 화면 요소 덤프"
   → 로그에 `text / id / desc / center` 출력 + 클립보드 복사 → 셀렉터 작성
   - 셀렉터 키: `text`, `text_contains`, `text_regex`, `id`, `id_contains`, `desc`, `desc_contains`, `class`, `clickable`, `index`
   - 템플릿 변수: `{ticker} {ticker_re} {name} {exchange} {qty} {price} {stop_price} {side} {order_type} {order_type_label}`
   - step: `tap`, `tap_xy`(좌표), `type`, `wait`, `wait_for`, `key`(BACK/HOME), `swipe`, `shot`
   - 제출 버튼 step 에 반드시 `"final": true`
   - 예시 설정의 `매수`, `주문유형 선택`, 주문유형 문구는 앱 화면 기준이고 나머지 셀렉터는 예시 → 덤프로 교체

## 거래시간
- 기본: 미국 정규장 09:30~16:00 (뉴욕 시간, 평일, 서머타임 자동 반영)
  - 한국시간 기준 겨울 23:30~06:00, 서머타임 22:30~05:00
- 프리/애프터까지 허용하려면 `risk.trading_hours` 를 넓힘 (예: `["04:00","20:00"]`)
- 일일 주문 한도도 **미국 거래일 기준**으로 집계 (밤샘 장이 한국 날짜 두 개에 걸쳐도 하루로 계산)
- 미국 휴장일·조기폐장은 처리하지 않음

## 테스트 순서
1. "검사만" — 파싱 + 리스크 검사 (예: `TMV 매수 1주 지정가 43.38`)
2. "주문 승인 알림 테스트" — 알림이 뜨고 승인/거부가 동작하는지
3. 신한앱 **수동 로그인** 후 "실행" (`dry_run: true`) → verify 까지 확인하고 제출 직전에 멈춤, 캡처 저장
4. 장중 소액(1주) `dry_run: false` 로 실전 테스트 (승인 알림에서 승인)
5. 이후 신호앱 알림이 오면 자동 실행 → 승인 알림 → 승인 시 제출

## 업데이트 (앱 실행 시 자동)
- 앱을 열면 GitHub 최신 릴리스(`v<번호>`)와 현재 버전 비교
- 새 버전이 있으면 팝업 → [업데이트] → 다운로드(SHA-256 검증) → 시스템 설치 화면에서 확인
- 수동 확인: 첫 화면 "업데이트 확인"
- 배포(개발자): 기본 브랜치에 push → GitHub Actions 가 테스트·빌드 → 릴리스 `v<빌드번호>` 자동 게시
  - 파일명 `sinhanmacro_v<번호>_<빌드날짜>.apk`, 앱 `versionCode` = 빌드번호

## 최초 1회 설정: 서명 암호 시크릿 (필수)
- 업데이트 설치는 서명키가 매번 같아야 하므로 고정 키가 필요. 키는 저장소에 평문으로 올리지 않음
- 방법 (폰 브라우저에서 가능)
  1. GitHub 저장소 → Settings → Secrets and variables → Actions → **New repository secret**
  2. 이름 `SIGNING_PASSPHRASE`, 값 = 길고 아무도 모르는 문자열 (20자 이상) → 저장
  3. Actions 탭 → **Build APK** → Run workflow
- 동작
  - 첫 실행 때 CI 가 서명키를 생성하고 `SIGNING_PASSPHRASE` 로 **암호화**해 `android/keystore/release.jks.enc` 로 커밋
  - 이후 빌드는 같은 암호로 복호화해 같은 키로 서명 → 앱 내 업데이트 가능, 릴리스 자동 게시
- 주의
  - `SIGNING_PASSPHRASE` 를 잃어버리면 같은 키로 서명 불가 → 앱 삭제 후 재설치 (암호를 따로 보관)
  - 시크릿이 없으면 임시 키로 빌드만 하고 **릴리스는 게시하지 않음** (Actions 의 `apk` 아티팩트는 받을 수 있으나 업데이트 불가)
  - CI 가 키 파일을 커밋하므로, 로컬에서 푸시하기 전에 `git pull --rebase`

## 안전장치 요약
- 티커 정확 일치 + 화이트리스트, 종목별 `max_qty`, 지정가류 주문금액 상한(`risk.max_order_value`, 선택)
- 허용 주문유형 제한, 가격/감지단가 필수 검사, 소수점 수량 거부
- 일일 주문 한도, 동일 주문 중복 차단, 거래시간(뉴욕 시간)
- 제출 전 화면 검증(verify) + 사용자 승인(미응답 시 취소) + 승인 후 재검증
- 킬스위치 (첫 화면), 대상 앱이 전면에 없으면 조작 중단
- 제출 후 확인 실패 시에도 주문 기록 → 중복 주문 방지, 기본 `dry_run: true`

## 한계 / 주의
- **신한앱이 접근성 서비스 사용을 탐지·차단할 수 있음** → 먼저 접근성 ON 상태에서 신한앱이 정상 실행되는지 확인
- 보안화면(FLAG_SECURE)·보안키패드는 화면 요소·스크린샷이 막힐 수 있음. 로그인은 수동 (생체/간편인증 유지)
- 주문마다 비밀번호를 요구하면 자동화 불가
- 폰 화면 잠금(PIN/패턴)이 있으면 자동 실행 불가 → 잠금 없음 또는 충전 중 화면 유지 권장
- 방해금지 모드가 승인 알림을 숨길 수 있음 (그래도 앱 첫 화면에서 승인 가능)
- 앱 실행이 막히면 "다른 앱 위에 표시" 허용 후 재시도
- 스크린샷은 Android 11+ (저장: `Android/data/com.sinhanmacro.app/files/shots/`)
- 시장가는 금액 산정이 불가해 금액 상한이 적용되지 않음, 지정가는 호가 단위 일치 필요
- 신한앱 업데이트 시 flows 재작성 필요
- 약관 위반·계정 제재 가능성, 모든 매매 손익은 본인 책임
- 이 앱은 실제 신한앱/실기기에서 검증되지 않음 → 반드시 `dry_run` 으로 단계별 확인
